# Resume to Job-Description Fit Scorer

A small applied-AI service that accepts a job description and a PDF/TXT resume and returns a structured, criterion-by-criterion fit assessment.

The system is designed as a recruiter decision-support tool rather than an automatic hiring decision.

## 1. Problem

Given:

- a job description
- a candidate resume in PDF or TXT format

the system:

1. extracts the important hiring criteria from the job description
2. evaluates the resume against each criterion independently
3. produces evidence, reasoning, and missing requirements
4. applies configurable scoring weights
5. returns an overall fit score
6. applies a calibration step to reduce excessive score variation between similar resumes

---

## 2. Design

The system uses a two-stage LLM pipeline.

### Stage 1 - Job criterion extraction

Gemini extracts exactly five standardized categories:

- Skills
- Experience
- Education
- Responsibilities
- Domain

The categories are normalized so that every resume receives a consistent evaluation structure.

### Stage 2 - Criterion scoring

A second Gemini request evaluates all five criteria in one structured response.

Each criterion receives:

- score from 0 to 100
- supporting resume evidence
- reasoning
- missing requirements

The scoring anchors are:

| Score | Meaning |
|---:|---|
| 0 | No evidence or contradictory evidence |
| 25 | Weak or indirect evidence |
| 50 | Partial match |
| 75 | Strong match with minor gaps |
| 100 | Clear and direct match |

All scores must be supported by information explicitly present in the resume.

The system does not give credit for unstated skills or qualifications.

---

## 3. Calibration

Raw scores are compressed 15% toward the midpoint of 50:

```text
calibrated_score = 50 + 0.85 × (raw_score - 50)
```

This reduces the effect of small wording differences without making all scores equal.

For example:

```text
78 → 73.8
74 → 70.4
62 → 60.2
```

The project uses a 15-point gap as a calibration guardrail for the take-home demonstration.

This threshold is a project-level diagnostic and is not an industry-standard benchmark.

### Important calibration note

The calibration demonstration is designed to be reproducible without depending on the external Gemini service.

The script loads three sample resumes, reports their lexical similarity, and applies controlled raw scores to demonstrate the calibration behavior. It therefore does not claim that the displayed calibration scores were generated by a live Gemini evaluation.

Run:

```powershell
python calibration/run_calibration.py
```

The current sample demonstration produces:

```text
Resume A/B raw gap: 4.00 points
Resume A/B calibrated gap: 3.40 points

PASS: similar resumes remain within
the 15-point calibration guardrail.
```

---

## 4. Weighted scoring

The default scoring weights are configured in `app/config.py`:

| Criterion | Weight |
|---|---:|
| Skills | 0.40 |
| Experience | 0.25 |
| Education | 0.10 |
| Responsibilities | 0.15 |
| Domain | 0.10 |

The weights are configuration rather than being embedded in the scoring formula.

`normalized_weights()` normalizes the configured values before they are used.

Therefore, changing the relative weights does not require changing the scoring implementation.

## 7. Setup

Clone the repository and enter the project directory:

```powershell
cd Resume-to-Job-Description-Fit-Scorer
```

Create a virtual environment:

```powershell
python -m venv .venv
```

Activate it:

```powershell
.venv\Scripts\activate
```

Install dependencies:

```powershell
pip install -r requirements.txt
```

Create the environment file:

```powershell
copy .env.example .env
```

Add the Gemini API key to `.env`:

```text
GEMINI_API_KEY=your_api_key_here
```

The current model is configured as:

```text
GEMINI_MODEL=gemini-3.6-flash
```

Never commit the `.env` file or API key to GitHub.

## 11. Input validation and error handling

The API validates inputs before performing unnecessary LLM operations.

### Short job description

Job descriptions shorter than 80 characters return:

```text
HTTP 422
```

Example:

```json
{
  "detail": "Job description must contain at least 80 characters."
}
```

### Unreadable resume

If a PDF contains no extractable text, the API returns a controlled validation error rather than silently scoring an empty resume.

Example:

```text
HTTP 422
```

with a message similar to:

```text
Resume parser could not read any text.
Try a text-based PDF or TXT.
```

### File-size limit

The configured maximum resume size is:

```text
5 MB
```

Files exceeding this limit are rejected before LLM processing.

### Gemini failures

Gemini requests are wrapped in `LLMError`.

Temporary API failures can be retried with exponential backoff.

Quota exhaustion is deliberately not retried because repeated requests do not restore an exhausted quota.

The API converts an unrecoverable Gemini failure into:

```text
HTTP 502
```

rather than exposing an unhandled traceback.

## 12. Gemini quota limitation observed during testing

During end-to-end testing, the configured Gemini model successfully completed the first LLM request.

The second request returned:

```text
429 RESOURCE_EXHAUSTED
```

The API reported that the Gemini free-tier request quota had been exceeded.

The application correctly converted this external service failure into:

```text
HTTP 502 Bad Gateway
```

This means the complete local pipeline and Gemini integration are implemented, but a successful two-call live analysis could not be completed during the final test because of the external API quota.

This limitation is documented rather than hidden.

## 14. Calibration demonstration

Run:

```powershell
python calibration/run_calibration.py
```

The script:

1. loads three sample resumes
2. verifies that their text can be extracted
3. calculates a simple lexical similarity diagnostic
4. applies controlled sample raw scores
5. applies the calibration function
6. compares the score gap before and after calibration
7. checks the project-level 15-point guardrail

Example result:

```text
Raw scores:
  resume_a.txt: 78.00
  resume_b.txt: 74.00
  resume_c.txt: 62.00

Calibrated scores:
  resume_a.txt: raw=78.00 -> calibrated=73.80
  resume_b.txt: raw=74.00 -> calibrated=70.40
  resume_c.txt: raw=62.00 -> calibrated=60.20

Resume A/B raw gap: 4.00 points
Resume A/B calibrated gap: 3.40 points

PASS: similar resumes remain within the
15-point calibration guardrail.
```

The lexical similarity calculation is a lightweight diagnostic for this demonstration and is not presented as an industry-standard similarity metric.

## 15. Metrics

The API records:

### End-to-end latency

Measured in milliseconds from the beginning of `/analyze` until the response is prepared.

This helps understand the operational cost of the LLM-based pipeline.

### Calibration gap

The calibration demonstration measures the score difference between similar sample resumes before and after calibration.

This provides a simple stability diagnostic.

The project does not claim model accuracy because there is currently no large human-labeled benchmark dataset.

## 18. Safety and interpretation

The fit score is a decision-support signal, not an automatic hiring decision.

Recruiters should review the evidence, reasoning, and missing requirements before making a decision.

The system should not be treated as a substitute for human review.
